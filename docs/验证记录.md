# 验证记录

本仓库的恢复程序通过 CPU 测试验证。机器可读的实际结果见 `checksums/validation_report.json`。

## 合成分片端到端测试

测试构造 40 层、256 专家轴的小型分片及同格式检查点，覆盖：

- 40 个共享矩阵替换和 384 个专家切片置零。
- router、非目标专家、视觉与 MTP 示例张量保持不变。
- 原基模、配置及分片索引不被修改。
- ZIP 与已解压检查点两种入口。
- 损坏的包、额外 ZIP 成员、错误步数、名单或权重内容被拒绝。
- 路径越界、覆盖已有目录或在基模内部输出被拒绝。
- 模拟写入失败后保留未完成标记，不误报恢复成功。
- 从不同工作目录读取相对路径和含空格路径，仍能定位仓库内清单。
- 断开的输出符号链接被拒绝；无效输出路径或空间不足时不创建输出。

运行方式：

```bash
python -m unittest discover -s tests -v
```

## 真实输入的 CPU 验证

检查真实恢复包的固定哈希、40 个真实 BF16 张量及 384 专家名单；检查基模索引中实际涉及的全部 79 个目标张量形状（40 个共享矩阵与 39 个专家打包矩阵）；对真实共享矩阵执行替换验证，并在第 20 层的真实路由专家打包矩阵上验证置零轴与非目标专家不变。

如需在自己的基模副本上重做该检查，请在仓库根目录按使用说明的摆放方式运行：

```bash
python tests/validate_real_inputs.py \
  --base ../Intern-S2-Preview \
  --package ../B26_restore_weights_v1.zip \
  --report ../B26-validation-report.json
```

## 验证范围

当前工作区没有足够额外空间再保存一份约 73 GB 的完整模型，因此**没有在此工作区实际写出完整恢复模型并执行整模型推理**。已完成的是合成分片端到端测试与真实目标张量 CPU 检查，不能将其表述为完整模型落盘/推理实测。

接收方执行正式恢复时，程序仍会逐分片重新读取写出内容，核验全部输出张量，并生成该次恢复自己的 `recovery_report.json`。
