# 使用说明

## 一、需要准备什么

1. 完整、未编辑的 `Shanghai_AI_Laboratory/Intern-S2-Preview` 基模目录。必须包含 23 个原始权重分片，以及配置、分词器和自定义模型代码。不能用语言祖先模型、量化模型或其它版本替代。
2. 微信单独分发的 `B26_restore_weights_v1.zip`。其中只有 `B26_locked_BF16.pt`，约 80.02 MiB；ZIP 约 63.76 MiB。也可以直接使用已解压的检查点文件。
3. 本仓库的程序和校验清单。

基模下载位置可能随上游更新而变化，因此不以“模型名称相同”代替身份确认。脚本以 `checksums/base_manifest.json` 中的文件哈希为准，不会自动下载或切换基模。

## 二、环境准备

已验证的环境为 Linux、Python 3.12、PyTorch 2.8.0、safetensors 0.8.0、NumPy 2.5.4。恢复操作只用 CPU，建议至少 16 GiB 内存、推荐 24 GiB；较多内存可减少系统换页。

```bash
git clone https://github.com/HoshiuZ/intern-s2-unlearning-v1-recovery.git
cd intern-s2-unlearning-v1-recovery
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install torch==2.8.0 --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements.txt
```

如果已有合适的 PyTorch 环境，可以直接安装 `requirements.txt`。恢复程序本身不需要安装 Transformers，也不需要 CUDA。

## 三、先校验输入

```bash
python scripts/restore_model.py \
  --base /path/to/Intern-S2-Preview \
  --package /path/to/B26_restore_weights_v1.zip \
  --verify-only
```

此模式会核验 ZIP、内部检查点、40 个 BF16 共享矩阵、384 个消融专家名单，以及完整基模的文件哈希。读取约 73 GB 基模来计算哈希需要时间，具体耗时取决于存储速度；不会生成完整模型。

## 四、恢复完整模型

输出盘需在基模以外再留足空间。程序根据清单检查保守空间需求，建议至少 90 GB 可用空间。输出目录必须是一个尚不存在的新目录：

```bash
python scripts/restore_model.py \
  --base /path/to/Intern-S2-Preview \
  --package /path/to/B26_restore_weights_v1.zip \
  --output /path/to/Intern-S2-B26 \
  --threads 4
```

如果使用已解压文件，将 `--package` 换成：

```bash
--checkpoint /path/to/B26_locked_BF16.pt
```

两种入口二选一。ZIP 入口在内存中读取检查点，不会额外解压一份检查点到磁盘。

恢复过程包括：

1. 校验输入身份。
2. 将第 0–39 层的 40 个共享专家 `down_proj` 完整替换为恢复包中的 BF16 张量。
3. 将固定名单中 384 个路由专家的 `down_proj` 矩阵切片置零。原模型该投影无偏置，因此等价于将对应专家输出置零；不改变 router、top-8 选择或门控权重。
4. 逐分片保存并重新读取，对写出的每个张量核验形状、类型及哈希。
5. 其余文件原样复制并校验；视觉、时序、MTP 分支以及非目标张量保持不变。

程序不会重新训练、重新挑选专家或调整权重幅度，也不会修改原基模。

## 五、确认恢复完成

输出目录中应有 `recovery_report.json`，其中状态为“恢复完成，全部输出已校验”。成功完成时不会保留 `RECOVERY_INCOMPLETE.json`。

最终输出是完整模型目录，已经包含共享矩阵替换和专家置零，不需要在推理时再运行恢复脚本或安装消融钩子。

## 六、可选的模型加载

恢复与推理是两件事。后续加载完整多模态模型需要另备推理环境和相应内存/显存；本项目使用双 48 GB RTX 6000 Ada、BF16 和 eager 注意力进行评分。

`requirements-inference.txt` 给出已验证的主要推理依赖。需要 GPU 推理时，应先安装匹配驱动的 PyTorch/CUDA 版本，再安装该文件中的其它依赖，避免将仅用于恢复的 CPU 环境直接当成 GPU 推理环境。

```python
import torch
from transformers import AutoModelForImageTextToText, AutoTokenizer

model_dir = "/path/to/Intern-S2-B26"
tokenizer = AutoTokenizer.from_pretrained(
    model_dir, trust_remote_code=True, local_files_only=True
)
model = AutoModelForImageTextToText.from_pretrained(
    model_dir,
    trust_remote_code=True,
    local_files_only=True,
    dtype=torch.bfloat16,
    device_map="auto",
    attn_implementation="eager",
)
model.eval()
```

这是加载示例，不是对任意显卡的显存保证；设备映射应按实际硬件配置。若需复现评分，还需保持评分模板、完整四序列实现和注意力后端一致。基模原有源码与许可证由输出目录中的原始文件保留。
