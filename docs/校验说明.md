# 校验说明

## 恢复包身份

| 文件 | 字节数 | SHA256 |
|---|---:|---|
| `B26_restore_weights_v1.zip` | 66860391 | `697406d403fafe2a8bab145351ea93146f6271ed2c681ef6c967e2f4733f7c9a` |
| `B26_locked_BF16.pt` | 83909019 | `dee4e0208e7c5986ce5775d2da0efda2245dfbb49a9e85325d309a73879f9f9a` |

Linux 可先用以下命令检查收到的 ZIP：

```bash
sha256sum /path/to/B26_restore_weights_v1.zip
```

恢复程序会再次校验 ZIP 与内部检查点。`checksums/checkpoint_manifest.json` 还包含每个共享矩阵的形状、BF16 类型、张量内容哈希及固定的 384 专家名单。张量内容哈希按连续 CPU 张量的原始字节计算；BF16 不转换成 FP32 再计算。

## 基模身份

`checksums/base_manifest.json` 列出完整基模所需文件的相对路径、大小及 SHA256，含 23 个权重分片。脚本在创建输出目录之前先核验这些文件。额外下载缓存不参与恢复，也不会被复制到输出模型。

清单中不包含原实验机器的绝对路径。检查点记录的原始基模清单摘要作为身份字段保留，使用者不需要取得实验机器上的原始清单文件。

## 输出校验

对于需要修改的分片，程序在写出前记录每个张量的预期哈希，再从写出的 safetensors 分片重新读取并比较。检查内容包括：

- 共享矩阵与恢复包逐元素对应，保持 BF16。
- 指定路由专家切片为零，其余切片保留。
- 非目标张量、张量集合、形状、类型以及分片元数据保持一致。
- 不需修改的文件原样复制，输出文件哈希与基模清单一致。

`recovery_report.json` 保存最终分片哈希与操作结果。修改过的分片哈希应当不同于原基模；不要再用原基模的分片哈希去要求恢复后模型相等。

## 出错时如何处理

- 输入哈希不匹配：停止使用该输入，核对传输是否完整、基模版本是否正确；不要通过删除校验代码强行恢复。
- 输出目录已存在：工具拒绝覆盖。请检查原目录，再指定一个新的输出目录。
- 写入失败或中断：输出中保留 `RECOVERY_INCOMPLETE.json`，该目录尚不可用于推理。工具不会自动删除失败现场。
- 磁盘或内存不足：补足资源后使用新的输出目录重试。需要的空间是完整模型输出空间，不是 ZIP 的大小。

本仓库没有自动清理历史文件、原地修改基模、联网下载权重或提交 GPU 作业的操作。
